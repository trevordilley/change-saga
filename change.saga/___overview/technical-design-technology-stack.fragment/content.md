This is the shared technology reference for the [Architecture whiteboard](/technical/whiteboards/architecture). The repository's contribution policy calls for a deterministic, dependency-light, local core. The table distinguishes documented decisions from benefits visible in the implementation; it does not invent historical selection discussions.

| Choice | Responsibility and rationale | Constraint or consequence |
| --- | --- | --- |
| Go and its standard library | The compiled CLI and loopback HTTP reader share domain packages, `net/http`, `html/template`, filesystem operations and embedded assets. A single binary fits the documented local, dependency-light distribution model. | CLI and server compose the same repository packages; this is not a separately deployed service architecture. |
| Git plus small JSON records and authored assets | Git supplies commits, diffs and ordinary collaboration. Stable identities and separate revision/event files keep independent changes small and inspectable. | Concurrent changes can still create competing heads. Git does not decide which product statement is correct. |
| JSON Schema (`santhosh-tekuri/jsonschema`) | Machine-readable contracts complement the Go validators; schema conformance is exercised in format tests. | Structural validity cannot establish that a diagram or explanation is true. The manifest establishes use, not an undocumented historical reason for selecting this implementation. |
| Goldmark | Shared Markdown rendering supports Essays and notes; default escaping and link restrictions preserve the authored-content boundary. | Safe Markdown is deliberately narrower than arbitrary executable HTML. Namespace handling matters when several documents share a page. |
| Vendored htmx plus plain JavaScript | htmx reuses server-rendered HTML and swaps the changing page within a persistent shell. The documented choice avoids a second client-side markup renderer and a runtime CDN dependency. JavaScript handles diagrams, decks, annotations and local interaction state. | Page lifecycle cleanup and cache invalidation are explicit responsibilities. There is no Redux/TanStack Query application layer. |
| Native diagram grammar and SVG | Explicit geometry, nested sections, connections and theme tokens drive one deterministic renderer used by structured slides and whiteboards. Bundled fonts and icons avoid runtime asset fetching. | Authors choose layout and inspect readability. Valid geometry does not guarantee an informative diagram; source adapters remain limited. |
| Disposable filesystem cache generations | Fingerprinted inputs address derived content outside the Saga. Staging and atomic rename publish complete generations; deleting them changes latency rather than authored state. | Unpinnable inputs must bypass persistent reuse. Cache boundaries must follow the inputs actually read. |
| Go tests and Playwright | Go suites exercise model, CLI and server contracts. Browser suites exercise real rendering, navigation and interactions. TypeScript supports the browser test harness. | These are development tools, not a second application runtime. CI results are separate from authored test-case definitions. |

The Go module manifest is the authoritative version source for Go dependencies; the vendored asset version files and `e2e/package.json` serve that purpose for browser assets and test tooling. Keep this page about the meaningful choices and their consequences rather than duplicating a dependency lockfile.
