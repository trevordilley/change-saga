Change Saga helps product managers, designers, architects and developers understand an application as it evolves. Product pages explain personas, durable features, stories and acceptance criteria in authored prose. A criterion keeps its full pass/fail statement alongside an optional short title and detailed explanation.

[Technical design](/technical) is an approach essay linked to three whiteboards: [ERD](/technical/erd), [Infrastructure](/technical/whiteboards/infrastructure) and [Data flows](/technical/whiteboards/data-flows). Implementation decks explain individual mechanisms; pull-request decks explain changes with exact code evidence, contextual discussion and explicit review decisions.

The CLI authors and queries the same versioned files that the local browser reads. Git retains their history, source pins make evidence inspectable, and derived coverage or readiness reports expose gaps without claiming correctness. This Saga documents the local application on main; the separate hosting work is deferred.
