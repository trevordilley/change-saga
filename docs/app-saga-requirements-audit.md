# App Saga requirements audit

Audited the product contract, CLI surface, reviewer behavior, tests, and the complete current requirement graph on 2026-09-20.

## Findings and changes

- The three active personas are valid human beneficiaries but were underspecified. `change-author`, `reviewer`, and `newcomer` now state the value each person needs; the already-retired non-human `coding-agent` remains historical.
- Seven existing story identities remain accepted and were revised in place around human outcomes: `companion-repositories`, `coverage-report`, `first-change`, `observe-or-compare`, `overview-and-terms`, `review-is-pr-deck`, and `why-things-changed`.
- Eleven technical or duplicate story IDs were retired with explicit replacement reasons: `changed-lines-accounted`, `check-covers`, `code-references`, `documentation-not-approval`, `durable-features`, `growth-not-debt`, `one-app-saga`, `open-observe-or-compare`, `sidebar`, `traceability-chain`, and `two-sides`. Their surviving value moved into criteria or the replacement stories below; their history remains intact.
- Eleven accepted stories now cover missing human-value workflows: `bounded-automation`, `claims-verification`, `controlled-release`, `design-intent`, `evidence-repair`, `evidence-traversal`, `evolve-product-knowledge`, `parallel-delivery-plan`, `prototype-feedback`, `quality-evidence`, and `safe-local-review`.
- Six immutable provenance citations were added for the product overview, lifecycle, format, work-plan, automation-interface, and security contracts.
- Existing design and quality links were repinned while obligations were refined. Ten links that targeted retired technical stories were superseded only after equivalent links to current human-outcome stories were added. No story relation remains stale.

Three implemented capabilities received an explicit final disposition because each has distinct human value: `design-intent` covers requirement-linked UX and technical design before implementation; `claims-verification` separates falsifiable author assertions from independent verification and test-run evidence; `safe-local-review` covers local isolation for untrusted authored content. None was folded into a storage or command story.

Validation passes with 18 accepted persona-focused stories, 11 explicitly retired historical stories, and 146 one-line acceptance criteria.

## Out-of-scope follow-up

The requirements now expose the expected downstream work rather than fabricating it: 14 accepted stories lack design coverage and 144 criteria lack test-case coverage. One pre-existing stale code reference remains in the `two-sides` design landmark because its source lines changed; repairing design evidence is outside this audit's ownership.

## CLI dogfooding findings

1. **Use the repository's current v5 CLI.** Goal: validate and query the existing Saga. Command: `change-saga validate --json app.saga`. Observed: the installed binary rejected v5 as unsupported and reported the app roots as unknown. Impact: blocked. Workaround: used `go run ./cmd/change-saga` consistently. Smallest improvement: when a checkout contains a newer local CLI, report the executable/version mismatch and the exact local invocation instead of format errors.
2. **Read complete persona state through the query API.** Goal: audit names, descriptions, lifecycle, and story coverage. Commands: `go run ./cmd/change-saga query requirements --saga app.saga --limit 100`, `go run ./cmd/change-saga status --json app.saga`, and `go run ./cmd/change-saga query history --saga app.saga --node urn:change-saga:app:persona:reviewer`. Observed: requirements omitted personas, status omitted persona descriptions, and history exposed file history but not the current definition. Impact: slowed the audit. Workaround: combined status with Git history. Smallest improvement: add paginated `query personas` with current revisions and lifecycle heads.
3. **Revise a corpus safely.** Goal: preserve IDs while rewriting one story and its criteria. Command: `go run ./cmd/change-saga story revise --feature code-evidence --story urn:change-saga:app:story:changed-lines-accounted --revision r3 --parent urn:change-saga:app:story:changed-lines-accounted:revision:r2 --title "See every unexplained part of a change" --statement "As a reviewer, I can see whether every changed line is connected to an explanation, so that I can spot unexamined parts of the change." --persona urn:change-saga:app:persona:reviewer --citation urn:change-saga:app:citation:app-saga-goals --criterion "in-some-range=The coverage view marks each changed line as explained or unexplained." --criterion "computed-not-stored=Coverage updates when the selected comparison changes without requiring an author-maintained coverage record." --criterion "ownership-accumulates=Unexplained legacy code does not block review when every line in the current change is explained." --json app.saga`. Observed: the single mutation was clear and history-safe, but 18 independent revisions had no corpus-level dry run or atomic batch. Impact: slowed work and made interruption leave a valid but partial audit. Workaround: ran a fail-fast script, then re-queried every head. Smallest improvement: accept an atomic JSONL batch of story/persona mutations with dry-run output.
4. **Create an accepted sourced story.** Goal: add a fully decided requirement. Commands: `go run ./cmd/change-saga story add --feature code-evidence --id evidence-repair --revision r1 --event proposed ... --json app.saga` followed by `go run ./cmd/change-saga story set-state --feature code-evidence --story urn:change-saga:app:story:evidence-repair --event accepted --parent urn:change-saga:app:story:evidence-repair:event:proposed --state accepted --reason "The public evidence workflow supports staleness diagnosis, scrutiny-ranked mappings, atomic replacement, remapping, and post-merge refresh." --json app.saga`. Observed: both commands were safe, but every already-decided story required a second mutation and a manually reconstructed event URN. Impact: slowed work. Workaround: used the deterministic proposed event ID. Smallest improvement: let `story add` optionally create a sourced accepted lifecycle event with an explicit reason.
5. **Reconcile all stale pins after a wording pass.** Goal: keep valid design and quality links current. Commands: `go run ./cmd/change-saga query relations --saga app.saga --state stale --limit 100` followed by eleven separate `go run ./cmd/change-saga relation repin --feature <feature> --relation <urn> --rationale <text> --json app.saga` calls. Observed: stale reasons and defaulted-pin output were excellent, but no safe batch or generated command set existed. Impact: slowed work. Workaround: repinned each relation and queried stale state again. Smallest improvement: add atomic `relation repin --batch FILE|-` with per-relation rationale and dry-run.
6. **Replace a relation without a half-migrated graph.** Goal: move proof from a retired technical story to its human-outcome replacement. Commands: `go run ./cmd/change-saga relation add --feature code-evidence --id resolve-test-verifies-evidence-remap --type verifies --from urn:change-saga:app:test-case:resolve-remaps-and-stales --to urn:change-saga:app:story:evidence-repair:criterion:moved-lines --rationale "The resolver test verifies that unchanged moved lines are remapped." --json app.saga` and then `go run ./cmd/change-saga relation supersede --feature code-evidence --relation urn:change-saga:app:relation:resolve-test-verifies-remap-or-stale --json app.saga`. Observed: successful but non-atomic; `supersede` also records no reason or replacement link. Impact: slowed work and briefly left both relations active. Workaround: added replacements first, superseded old links, then validated. Smallest improvement: add an atomic `relation replace` mutation carrying the old relation, complete new relation, and explicit reason.
7. **Check authoring quality, not only schema validity.** Goal: enforce persona value and one-assertion criteria. Command: `go run ./cmd/change-saga validate --json app.saga`. Observed: validation correctly checked the format but accepted technical beneficiaries, system statements, duplicates, and compound criteria. Impact: slowed editorial QA rather than blocking it. Workaround: queried all active stories and used targeted `jq` checks plus human review. Smallest improvement: add an opt-in `lint requirements --json` that flags missing persona/value phrasing, duplicated active story intent, multiline criteria, and likely compound assertions without making them schema errors.
8. **Inspect only the status slice needed.** Goal: retrieve persona and coverage summaries. Command: `go run ./cmd/change-saga status --json app.saga`. Observed: the response exceeded 100,000 tokens because every gap and generated next-action command was embedded; ordinary terminal output truncated it. Impact: slowed inspection. Workaround: redirected to a temporary file and projected fields with `jq`. Smallest improvement: add `status --summary` and rely on dedicated paginated queries for detailed gaps and personas.
