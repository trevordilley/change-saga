# Lasting documentation and change review {#two-sides}

A reader always knows whether they are learning the product as it exists or
evaluating one proposed change. Documentation preserves the current product
account; Review holds temporary comparison context, discussion, and decisions.
The distinction is durable navigation state, not a sidebar trick.

## Documentation preserves product truth {#documentation-side}

Documentation answers “What is this application?” It begins at the overview and
continues through features, requirements, design, quality, and implementation.
Pages remain free of approval and comment controls so a later reader does not
mistake an old review judgment for current truth.

The application overview and feature hierarchy are the lasting information
architecture. A reader can deep-link to a chapter, fragment, landmark, story, or
criterion and return through normal browser history.

## Review evaluates one change {#review-side}

Review answers “What is changing, why, and is the explanation sufficient?” One
selected comparison scopes its review deck, changed documentation, affected
documentation, code view, coverage omissions, comments, and decisions. Review
controls appear only in this mode and always retain the reviewed base and head.

Switching sides preserves the nearest meaningful destination. From a
documentation target, Review opens the related review context when one exists;
from Review, Documentation opens the lasting target referenced by the current
item. When there is no direct counterpart, each side opens its own overview
instead of fabricating a link.

## Resume without losing context {#resume-context}

URLs own the selected side, comparison, chapter or slide, and focused item or
file. Browser Back and Forward reconstruct the same context. Local progress may
suggest the next unfinished slide or file, but it never replaces a stable URL,
silently changes the selected comparison, or marks unread content complete.

A merged review remains reachable from the documentation it changed. Its deck,
comments, decisions, and currency history become read-only historical evidence;
the documentation itself remains the current account.

## Derived bridges stay subordinate {#related-reviews}

A feature, story, or criterion may list reviews that changed the code it
explains. The list is derived by intersecting review changes with existing code
ownership, labels itself as derived, and is absent when there is no match. It is
a contextual bridge, not authored proof and not a second source of truth.
